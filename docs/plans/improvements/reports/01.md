## Outside scope

- `apps/storybook/tsconfig.json` does not include `visual/`, so `typecheck` does not cover the Playwright config and the spec. That file is not in the Ownership list; Playwright transpiles both at run time and `--list` proves they load.
- The plan's readiness snippet waits on the render phases `completed` and `played`. Storybook 10.6.2 also reports `finished` after the play function and its cleanup, so the spec settles on `completed | played | finished` through `currentRender.phase` and fails the test on `errored | aborted`, with the story id in the message.
- `__screenshots__/.gitkeep` exists because the `docs` check resolves the code-span path of `CONTRIBUTING.md` on disk; the folder is empty until the update job writes the first Linux baselines. The check mode still fails early when no PNG is present.

## Open risks

- No baseline is committed yet: the first run of `Visual regression` stops at "Require the baselines" until the update job produces them, and the bot commit starts no run, so the check must be re-run by hand after the label is removed.
- The host runs prove determinism, not pixel parity with Linux: the first Linux comparison may differ from nothing but itself, then from the host only in rasterisation that the update mode accepts once.
- Zero tolerance means any deliberate change fails the pull request until the label runs, at a cost of about 10–12 minutes and 31 MB of committed PNG per full pass.
- `actionlint` is absent, so the workflow is proven only by a YAML parse and by reading it; its first real run happens on the pull request.
- The check pulls `mcr.microsoft.com/playwright:v1.63.0-noble` on every run: a registry outage blocks the gate.
