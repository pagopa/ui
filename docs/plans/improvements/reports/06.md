## Outside scope

- `packages/ui-cli/src/cli.ts`: the citty command tree lives here and without
  the `align` entry the target prints `Unknown command align`. The file is not in
  the Ownership list; the edit is the two argument blocks only.
- `packages/ui-cli/src/parity/diff.ts` classifies every path that is not
  `radius` or `offset.` under the `type` family, so a padding or gap delta
  carries a type token (`text-mono--letter-spacing` for a render of 0). `align`
  keeps the classification untouched and derives the hint from the source value
  with the same vocabulary; fixing `kindOf` is outside this action.
- `.agents/skills/figma-to-code/references/visual-parity.md` still describes the
  per-case command loop for one node. It is not in Ownership; `delta.md` and
  `new-from-figma.md` now start at `align`, and that page could follow.
- The radius hint maps the theme's steps (8 → `rounded-lg`, 16 → `rounded-xl`,
  24 → `rounded-3xl`); the literal `rounded-<name>` would print `rounded-8`,
  which the theme does not define.

## Open risks

- `align` captures every committed case of the node in sequence: a node with 16
  cases takes about a minute, and the command cannot narrow to one case.
- Colour deltas never reach the mapping today: `classifyResults` treats them as
  type deltas and their values are strings, so the `text-`/`bg-`/`border-`
  branch is ready but unused until colour classification exists.
- The hint follows the source value on purpose (the delta token describes the
  render); if the classification later starts reporting spacing tokens for
  padding, both paths lead to the same class.
- The `--json` shape of `align` is new and has no consumer yet.
