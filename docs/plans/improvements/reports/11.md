## What changed

- `packages/ui-cli/src/figma/sync.ts`: the module existence checks resolve through
  `absolutePath`, so a registry `target.module` may be workspace-relative. The two
  identity reads that run before the existence report (`evidence-exceptions`
  cleanup and reverse API coverage) go through a `moduleExports` helper that
  returns nothing for a missing file, so the report names it as `module not found`
  instead of failing on the missing file first.
- `packages/ui-cli/src/checks/foundation.ts`: `measure` walks `src/components` and
  `apps/storybook/src/templates`; occurrences in the second root carry a
  workspace-relative `file`.
- `packages/pagopa-ui/src/components/templates/**` → `apps/storybook/src/templates/**`:
  eight files moved unchanged, `index.ts` (a barrel nothing imported) deleted.
- `apps/storybook/src/{LogIn,FeedbackPage,DialogTemplate,SecurityCodeDialog,InformativeDrawer}.stories.tsx`:
  one import line each, now `./templates/<Name>`.
- `packages/pagopa-ui/src/catalog/figma/registry.json`: 24 `target.module` values
  rewritten to `apps/storybook/src/templates/…`; no other field changed.
- `packages/tokens/src/foundation-exceptions.json`: the one `templates/` entry
  follows its file.
- `apps/storybook/vite.config.ts`: the coverage `exclude` entry for the templates
  is gone (`**/*.stories.*` stays).
- `packages/pagopa-ui/src/library.css`: the `@source not` line for the templates
  is gone.
- `packages/ui-cli/src/checks/import-layers.ts`: `templates` joins
  `REMOVED_LAYERS`, leaves `allowedLayers()` and loses its third-party exemption.
- `packages/pagopa-ui/project.json`: `figma:check` and `foundation:check` add
  `{workspaceRoot}/apps/storybook/src/**/*` to their inputs.
- Documentation: `CONTRIBUTING.md` (folder list), the standards'
  `definition-of-done.md` (layer lines) and the `import-layers.ts` row of
  `packages/ui-cli/README.md`.
