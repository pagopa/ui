## What changed

- `packages/ui-cli/src/checks/client-directives.ts`: new classifier and check.
  It walks `src/**/*.{ts,tsx}` (tests and stories excluded), decides "client"
  from the module's own source — hook call, `createContext`, JSX `on…=`
  handler, `window.`/`document.`, `@base-ui/react` or `react-day-picker`
  import — never from a client module it renders, never from a re-export-only
  barrel, and ignores triggers quoted in comments. `--report` prints `missing`
  and `unneeded` and exits 0; the default exits 1 on `missing` and warns on
  `unneeded`.
- `packages/ui-cli/tests/checks/client-directives.test.mjs`: fixtures for a
  hook, `createContext`, an `onClick=`, a Base UI import, a pure component, a
  re-export barrel, a directive without a trigger, a comment and the test/story
  exclusions.
- `packages/ui-cli/src/cli.ts`, `packages/ui-cli/package.json`,
  `packages/pagopa-ui/project.json`: the `check client-directives` command, the
  `client:check` script, and the `client:check` target added to `test.dependsOn`.
- 55 source modules: `"use client"` as the first line, above the first
  comment, with no other change.
- `packages/pagopa-ui/vite.config.ts`: `preserveModules: true`,
  `preserveModulesRoot: "src"` and an `entryFileNames` callback that keeps the
  entry at `dist/pagopa-ui.js`. The source directive survives the build, so no
  local `renderChunk` plugin was needed; `dist/node_modules/**` stays empty.
- `packages/ui-cli/src/checks/library-artifact.ts`: fails when a `dist` module
  whose source is a client module does not start with the directive; it reuses
  the classifier instead of duplicating it.
- `packages/ui-cli/src/checks/library.ts`: a second temporary consumer builds
  the App Router fixture with `pnpm exec next build` (`NEXT_TELEMETRY_DISABLED=1`,
  last 40 lines of output on failure), after the Vite consumer.
- `packages/ui-cli/tests/fixtures/library-rsc-consumer/`: `app/layout.tsx`
  (Server Component, imports the stylesheet), `app/page.tsx` (Server Component,
  no directive, renders `UIProvider` around `Button` and the server-safe `Tag`),
  `next.config.mjs`, `tsconfig.json` and `types.d.ts` (TypeScript 6 checks
  side-effect imports; Next declares only `*.module.css`).
- `packages/pagopa-ui/README.md`: "Next.js (App Router)" section.
- `packages/pagopa-ui/CHANGELOG.md` (`### Changed`), `.nx/version-plans/`: the
  release note and a `patch` plan.

## Outside scope

- `packages/ui-cli/tsconfig.json` was **not** in Ownership: the fixture had to
  join the `exclude` list next to `tests/fixtures/library-consumer`, otherwise
  `pagopa-ui-cli:typecheck` compiles the fixture's `.tsx` files without React
  types or a `jsx` flag. One entry added; please review it with the merge.
- Step 5.1 found no single-JS-file assertion in `library-artifact.ts` to rewrite:
  the artifact contract never read `dist/pagopa-ui.js` sizes or file lists, and
  the "no demo export" scan runs on the imported namespace, which a per-module
  barrel keeps intact. Nothing was removed; only the directive assertion was
  added.
- Step 6.1 asked for `next@latest`. The latest releases (16.3, 16.4) fail to
  render **any** App Router page on the React 19.2.8 the workspace resolves —
  even a bare Next app with no `@pagopa/ui` fails with
  `TypeError: Cannot read properties of null (reading 'useContext')` on
  `/_global-error`. The fixture therefore pins **16.2.12**, the newest release
  that builds on React 19.2.8, and the version lives in the `pagopa-ui-cli`
  devDependency and the workspace lockfile. A React bump to 19.3 would allow
  moving the fixture forward.
- The Playwright **visual** suite (action 01, `mcr.microsoft.com/playwright`
  Linux container) cannot run here: Docker is not installed on this machine.
  It is not part of `workspace:verify`, so the green chain was not affected.

## Open risks

- A consumer on Next 16.3+ and React 19.2.x is broken by Next itself, not by
  this package; the fixture cannot prove that combination until React moves.
- The Next.js build proves the RSC boundary only for modules that fail to
  render on the server (context, state). A missing directive on a component
  that happens to render without hooks is caught by the artifact assertion, not
  by `next build`.
- Splitting the bundle keeps the tree-shaking win per page but makes the
  package ship 490 files; a consumer's bundler now resolves many small modules
  instead of one. The packed check covers the installed tarball, not a
  consumer's dev-server cold start.
