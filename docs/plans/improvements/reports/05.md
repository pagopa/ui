## What changed

- `packages/ui-cli/playwright.config.mjs`: the engine projects come from
  `LIBRARY_ENGINES` (comma separated, unset means all three); an unknown name
  fails with the valid ones.
- `packages/ui-cli/src/checks/library.ts`: the success line names the engines
  that ran instead of always claiming the three.
- `apps/storybook/package.json`: `test:webkit` names the `storybook` project, so
  the pull-request pass no longer repeats `storybook-conditions`.
- `apps/storybook/project.json`: `test:stories` and `test:webkit` drop the
  `figma:check`, artwork and token test dependencies; the stories import the
  artwork and token sources, not their build output.
- `.github/actions/setup/action.yml` (new): the nine setup steps of the three
  jobs, with the token and the browser list as inputs and every pinned SHA kept.
- `.github/workflows/deep-checks.yml`: each job keeps its checkout and calls the
  composite action; the packed-artifact job computes its browser list by event
  and sets `LIBRARY_ENGINES=chromium` on the pull-request and push steps. The
  header names the engines per event; the three job `name:` values are identical.
- `tools/workspace/project.json` (new): `workspace:verify` runs the green chain
  one command per array item, without cache; `-c fast` stops before the browser
  suites and the Storybook build.
- `CONTRIBUTING.md`: "The green chain" starts with `workspace:verify`, names
  `-c fast` as the quick subset and keeps the expanded chain as "what it runs".
- `docs/plans/pipeline-proposal.md`: appended "Measured after action 05".

## Open risks

- The composite action only executes in CI; a mistake in it surfaces on the first
  run after the merge. Its steps are copied verbatim with the same pinned SHAs,
  and the cache keys keep the dash form the jobs used before (`chromium`,
  `firefox-webkit`, `chromium-firefox-webkit`), so the existing caches still hit.
- A regression that only Firefox or WebKit exposes in the packed artifact now
  reaches `main` before the nightly run finds it.
- The browser list reaches the cache keys through the `browsers` input, so
  another spelling of the same engines (extra spaces, a different order) opens a
  cold cache.
